MCP

Connect an AI agent to this workflow. Once connected, you can ask it to add packages and projects, or create and move your tasks, and the changes show up here live.

1. Your connection URL

One URL is all any agent needs: your token is part of it, so there is nothing else to configure. The guides below fill it in for you.

  • Generate a token to put it in the URL. It is valid for 30 days.
  • Generating a new token replaces the previous one, so agents using the old URL stop working.

2. Connect your agent

Claude

OpenAI

Editors and CLIs

Claude Code

Terminal and desktop-app sessions. One command, and it works in every project.

  1. Add the server for your user, so every project can use it. Drop --scope user to keep it to the current project.

    claude mcp add --transport http --scope user webart-work "https://it.webart.work/api/webartwork/mcp?token=YOUR_TOKEN"

  2. Check that it is connected. Inside a session, /mcp shows the same list.

    claude mcp list

3. Try it

  • "List my tasks that are in progress."
  • "Create a task "Review the pricing page" in the Web Art Work project and start it."

  • "Mark the task "Review the pricing page" as completed."

What the agent can do

Packages, projects, roadmaps, requests and plans are shared by the team (roadmaps, plans and what a roadmap links are public). Tasks are private: the agent only sees and changes the tasks of the token's owner. Good agents ask before deleting.

  • list_packagesList packages, optionally one category.
  • create_packageName, Github repo, optional npm link, description and category (ai, blockchain, angular, unity, waw).
  • update_packageChange any field of a package.
  • delete_packageDelete a package.
  • list_projectsList the team’s projects.
  • create_projectName, description, directions and links.
  • update_projectChange any field of a project.
  • delete_projectDelete a project.
  • list_developersThe developers and their ids, without email or phone number.
  • list_roadmapsRoadmaps with visitor vote scores and comment counts.
  • list_commentsWhat visitors commented under a roadmap or plan.
  • create_roadmapA bigger piece of work linking projects, tasks, packages and developers.
  • update_roadmapChange a roadmap, its links or its status.
  • delete_roadmapDelete a roadmap.
  • list_plansThe weekly development plans.
  • create_planPublish the plan for a week, split into packages and roadmaps.
  • update_planChange a plan.
  • delete_planDelete a plan.
  • list_requestsWhat visitors asked for: packages, roadmaps, improvements and bugs.
  • set_request_statusMark a request handled, or new again.
  • delete_requestDelete a request.
  • list_tasksYour tasks, filtered by status or project.
  • create_taskA new task for you, optionally in a project.
  • update_taskChange a task’s title, project or directions.
  • set_task_statusNew, in progress or completed. Records the week for the timeline.
  • delete_taskDelete one of your tasks.

When it does not connect

Test the URL outside any agent. A list of tools means it works and the problem is the agent's config; "Invalid or missing token" means the token is wrong, expired, or replaced.

PowerShell

Invoke-RestMethod -Method Post -Uri "https://it.webart.work/api/webartwork/mcp?token=YOUR_TOKEN" `
  -ContentType "application/json" `
  -Body '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

curl

curl -s -X POST "https://it.webart.work/api/webartwork/mcp?token=YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
  • Generating a new token revokes the old one, so every agent that used the old URL needs the new one.
  • Tokens expire after 30 days. The counter at the top shows how many days are left.
  • Apps read their config when they start: after editing it, quit the app fully and open it again.

Keep it safe

  • Anyone with the URL acts as you, with the same access to packages, projects and your tasks. Treat it like a password.
  • Never commit it. Keep it in your user-level config, not in a file that lives in a repository.
  • URLs can end up in server logs and screenshots, which is why the token expires after 30 days.
  • If it leaks, generate a new token: the old one stops working at once.
